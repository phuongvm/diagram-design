# Publication Manual Layout & Interactive Controls (`assets/template-manual.html`)

Start from `assets/template-manual.html` for any multi-section guide, runbook, or documentation portal index that embeds more than one section or more than one diagram. Single-column `assets/template-full.html` is reserved for single-hero diagrams only.

## 1. Required Document Structure (In Order)

1. `nav.top-nav` — brand link to `index.html` plus sibling-document navigation buttons; the active page carries `class="current"`.
2. `div.layout-frame` — CSS grid `260px 1fr`; collapses to one column under 900px.
3. `aside.toc-sidebar` — sticky, lists every `section[id]` of the article; use `.toc-group` labels for grouped portals.
4. `article[data-doc-archetype="<archetype>"]` — `div.report-meta-badge` (doc ID, edition), `h1.report-title`, `div.metadata-grid` (`.meta-item` label/value pairs), `div.quick-start-strip` (60-second action/TL;DR summary), auto-hydrated `nav.diagram-lens-jump-strip` (injected below `.quick-start-strip` by `<script data-manual-controls>` when figures carry `data-diagram-lens`), and `div.callout-box` with the one-paragraph decision summary.
5. Sections — `h2.section-heading`, then figures packaged as `div.diagram-container[id="fig-<slug>"][data-diagram-type="<slug-from-51>"][data-diagram-lens="<lens-id|supplemental>"]` > `div.diagram-header` (figure number and `VISUAL PATTERN` tag) + `div.diagram-viewport` (inline `<svg>`) + `div.diagram-caption` (takeaway and link to the standalone `diagrams/<slug>.svg`), plus visible `<div class="lens-waiver" data-waive-lens="<lens-id>" data-waive-reason="<>=24-char justification>">` blocks when an eligible conditional lens is waived. Audience/workflow splits go in `.role-tabs[data-role-tabs]`; tables go in `div.table-container`; code/command snippets go in adaptive Light/Dark `.code-block[data-code-block][data-wrap="on"]` cards; verbose schemas, checklists, and L4 audit evidence go in `<details class="ref-drawer">`.
6. `footer` — document reference line.

### 1.1 Document Archetypes (5 Canonical Archetypes & Mandatory Lens Series)

Declare `<article data-doc-archetype="<archetype>">` before drafting and satisfy the archetype's ordered mandatory progressive diagram lens series using allowed slugs from the **51-type catalog**. Full specification, reader questions, and complete 51-slug index live in [`references/diagram-series-matrix.md`](diagram-series-matrix.md). Every archetype follows the progressive reading order: **`60s Start Here (.quick-start-strip) → Diagram Lens Jump Strip → Progressive Mental Model Series → Action/Role Tabs → Collapsible Reference & Audit`**.

1. **`system-design`** *(system architecture, multi-service topologies, protocols, state/storage models, deployment boundaries)*:
   - **Mandatory Ordered Lenses**:
     1. `system-context` (`dp-integration`, `high-level`, `architecture`) — waivable **ONLY** for embedded or single-process libraries with zero external network boundaries (never for networked or deployed services).
     2. `architecture-overview` (`architecture`, `layers`, `nested`) — **non-waivable**.
     3. `user-interaction` (`service-blueprint`, `event-modeling`, `swimlane`, `journey`) — **non-waivable** (separates human/operator frontstage actions above the Line of Visibility from backstage system work).
     4. `low-level-design` (`db-schema`, `er`, `state`, `sequence`, `dependency`, `uml-class`, `data-flow`) — waivable only with explicit `>= 24`-char justification.
     5. `deployment` (`deployment`, `architecture`) — waivable **ONLY** for embedded or single-process libraries with zero external network boundaries (never for networked or deployed services); when `architecture` is selected for `deployment`, it **MUST** apply the **`Secure paved road`** semantic pattern (trust zones, hosts, ports, and permitted/forbidden ingress or deploy paths).
   - **Action/Role Tabs & Reference**: `.role-tabs[data-role-tabs]` or `.cards.stack` partitioning subsystem contracts (`Control Plane` / `Data Plane` / `Auth & Policy`), with wire schemas, SQL/DDL definitions, and verified code citations inside `<details class="ref-drawer">`.
2. **`user-operator-guide`** *(day-2 operations, CLI/API control, onboarding workflows, troubleshooting, prompt-driven playbooks)*:
   - **Mandatory Ordered Lenses**:
     1. `quickstart-steps` (`steps`) — **non-waivable**.
     2. `user-interaction` (`service-blueprint`, `journey`, `swimlane`) — **non-waivable**.
     3. `decision-routing` (`flowchart`, `state`, `org-chart`) — waivable only with explicit `>= 24`-char justification.
   - **Action/Role Tabs & Reference**: `.role-tabs[data-role-tabs]` separating execution modes (`Local Run` / `Remote Fleet` / `Failure Triage`), paired with `[data-prompt-builder]` cards when user-facing copyable prompts apply, and `<details class="ref-drawer">` drawers for CLI/env flag matrices and error catalogs.
3. **`runbook-migration`** *(cutovers, version upgrades, fleet rollouts, incident recovery, before/after architecture deltas)*:
   - **Mandatory Ordered Lenses**:
     1. `change-delta` (`architecture-delta`, `it-state`) — **non-waivable** (`1: Removals → 2: Moves → 3: Modifications → 4: Additions` when using `architecture-delta`).
     2. `execution-flow` (`swimlane`, `steps`, `sequence`, `gantt`) — **non-waivable**.
     3. `deployment-boundary` (`deployment`, `architecture`) — waivable only with explicit `>= 24`-char justification; when `architecture` is selected for `deployment-boundary`, it **MUST** apply the **`Secure paved road`** semantic pattern.
     4. `rollback-recovery` (`flowchart`, `git-graph`, `state`) — **non-waivable**.
   - **Action/Role Tabs & Reference**: `.role-tabs[data-role-tabs]` separating execution phases (`Pre-Flight` / `Cutover Execution` / `Rollback & Verification`), with rollout checklists and L4 smoke proofs in `<details class="ref-drawer">`.
4. **`data-pipeline`** *(ingestion/ETL/RAG pipelines, event-driven streams, medallion storage tiers, context learning loops)*:
   - **Mandatory Ordered Lenses**:
     1. `integration-topology` (`dp-integration`, `high-level`, `layers`) — **non-waivable**.
     2. `pipeline-flow` (`data-flow`, `process`, `event-modeling`, `medallion`) — **non-waivable**.
     3. `storage-or-loop` (`medallion`, `db-schema`, `er`, `loop`) — waivable only with explicit `>= 24`-char justification.
     4. `governance-access` (`dp-security-matrix`, `layers`) — waivable with explicit `>= 24`-char justification (for example, single-user local desktop applications); when `layers` is selected for `governance-access`, it **MUST** apply the **`Governance / control catalog`** semantic pattern.
   - **Action/Role Tabs & Reference**: `.role-tabs[data-role-tabs]` separating producer/processor/consumer contracts, with schema definitions, retention SLAs, and access matrices inside `<details class="ref-drawer">`.
5. **`strategy-analysis`** *(FinOps cost bridges, build-vs-buy evaluations, compliance/risk assessments, roadmap trade-offs)*:
   - **Mandatory Ordered Lenses**:
     1. `strategic-frame` (`architecture`, `wardley`, `quadrant`, `fishbone`, `requirement-traceability`) — **non-waivable**.
     2. `quantitative-model` (`waterfall`, `bar`, `sankey`, `unit-grid`, `heatmap`, `line`, `radar`) — **non-waivable**.
     3. `decision-roadmap` (`quadrant`, `flowchart`, `timeline`, `gantt`, `story-map`) — waivable only with explicit `>= 24`-char justification.
   - **Action/Role Tabs & Reference**: `.role-tabs[data-role-tabs]` or `.cards.stack` comparing strategic options or stakeholder impacts, with raw cost models, benchmark methodology, and citation ledgers inside `<details class="ref-drawer">`.

**HTML5 Tagging & Waiver Contract**: Every `.diagram-container` (or `figure.diagram-figure`) inside `<article data-doc-archetype="...">` MUST declare a unique `id`, `data-diagram-type="<slug-from-51>"`, and `data-diagram-lens="<mandatory-lens-id|supplemental>"`. Legitimate waivers on eligible conditional lenses MUST render as visible editorial prose inside `<article>` via `<div class="lens-waiver" data-waive-lens="<lens-id>" data-waive-reason="<>=24 non-whitespace char non-placeholder justification>">...</div>` (never `<meta>` tags, never on non-waivable lenses, and never duplicating or conflicting with a present figure).

### 1.2 Visual Density & Anti-Clutter Hard Rules

- **Card Grid Budget (`.cards.two` vs `.cards.stack`)**: Multi-column `.cards` (`div.cards.two` — **max 2 columns**, never 3+ columns on prose; collapses to `1fr` at `max-width: 720px`) is permitted **only** for short scannable summary cards (`<= 3` short bullets or `<= 60` words per card, and **zero** embedded `.code-block` or `<pre>`). Dense comparisons (`In Scope / Out of Scope`, role workflows, engineering seams, or cards containing commands/code) **must** use `.role-tabs[data-role-tabs]`, single-column `.cards.stack`, or `<details class="ref-drawer">`.
- **9-Line Auto-Collapsible Code Blocks & CRLF Normalization**: `initCodeBlocks()` normalizes Windows CRLF line endings via `rawCode.replace(/\r\n?/g, '\n').split('\n')` (preventing double-empty-line rendering bugs). Any `[data-code-block]` with `> 9` lines defaults to collapsed at 9 visible lines (`data-code-collapsible="true" data-code-expanded="false"`) with a smooth zero-shadow bottom fade overlay and an `Expand (N lines)` / `Collapse` toggle button (`[data-code-expand]`), unless opted out with `data-code-expanded="true"`. `Copy` (`[data-code-copy]`) **always** copies the full normalized `rawCode` even while collapsed, and both no-JS and `@media print` render the full code unclipped.
- **Balanced Tables & Soft-Wrapping Inline Code**: Tables keep balanced column proportions — identifier columns (`td.skill`) wrap cleanly (`white-space: normal; overflow-wrap: anywhere; word-break: break-word; max-width: 240px;`) instead of using rigid `white-space: nowrap` that crushes adjacent prose columns. Inline `code` soft-wraps across narrow containers (`overflow-wrap: anywhere; word-break: break-word; -webkit-box-decoration-break: clone; box-decoration-break: clone;`).
- **Full-Width Reading & Dual Sidebar Toggle Compatibility**: Standalone manuals collapse `aside.toc-sidebar` via `[data-toc-toggle]` or `[` (`article` expands from `920px` to `100%`). When compiled into the Knowledge Base web shell (`ai_agents/knowledge-base`), the same manual markup aligns with dual sidebar shortcuts (`[` left navigation sidebar, `]` right TOC sidebar) and stepped reading widths (`920px` both open → `1180px` one collapsed → `100%` both collapsed).

## 2. Customization & Migration Rules

- Keep every inline SVG unchanged when migrating an older page; preserve existing section and row anchor IDs (`#skill-*`, `#os-*`, `#fig-*`) and cross-links.
- Vary only `--doc-accent` and `--doc-accent-tint` per document; add no external CSS/JS framework.
- Wrap long inline code tokens on narrow viewports with `code { overflow-wrap: anywhere; word-break: break-word; -webkit-box-decoration-break: clone; box-decoration-break: clone; }` (block code soft-wraps by default inside `.code-block[data-wrap="on"]` and scrolls horizontally only when toggled to `data-wrap="off"`) — unspaced file paths and error constants inside `.callout-box` or `.card` otherwise breach container borders at `375px` mobile widths.
- Do not include `<link rel="preconnect">` tags for font domains; use only the single authorized Google Fonts stylesheet `<link>` to satisfy single-file and remote-reference safety in `scripts/self_check.py`.
- The one permitted script is the canonical `<script data-manual-controls>` copied verbatim from `assets/template-manual.html`.

## 3. Interactive Controls, Progressive Disclosure & Adaptive `--svg-*` Polarity

All interactive controls are inert without JavaScript so the page reads complete as static HTML:

- **Collapsible TOC & Theme Toggle**: `[data-toc-toggle]` in `.top-nav` collapses the sidebar to a full-width article (also via the `[` key outside text inputs); omit it on single-column pages. `[data-theme-toggle]` pins `html[data-theme="light"|"dark"]`; both persist in `localStorage`.
- **Progressive Disclosure Primitives (`.quick-start-strip`, `.diagram-lens-jump-strip`, `details.ref-drawer`, `.role-tabs[data-role-tabs]`)**:
  - *60-Second Summary Strip (`.quick-start-strip`)*: Compact above-the-fold TL;DR strip (`border-left: 4px solid var(--doc-accent)`, zero `box-shadow`) holding `.quick-start-head` and responsive `.quick-start-items` > `.quick-start-item` cells (`.quick-start-step` + 1-sentence action).
  - *Diagram Lens Jump Strip (`.diagram-lens-jump-strip`)*: Auto-hydrated immediately below `.quick-start-strip` by `initDiagramLensJumpStrip()` in `<script data-manual-controls>` using DOM-safe `createElement` calls (`zero innerHTML`). Renders the document's archetype pill plus ordered `[data-lens-jump]` figure links (with `IntersectionObserver` scrollspy `.is-active` highlighting) and `[data-lens-waived]` chips; injects `style[data-manual-lens-fallback]` on standalone manuals when `--manual-lens-strip` is unset, hides `.diagram-lens-jump-strip` in `@media print` while keeping `.lens-waiver` visible, and exits as a clean no-op on untagged legacy pages.
  - *Reference & Audit Drawer (`<details class="ref-drawer">`)*: Native collapsible `<details class="ref-drawer">` > `<summary>` + `<div class="ref-drawer-body">` with a pure-CSS geometric chevron indicator (`::after`), `break-inside: avoid`, and automatic full expansion on print (`beforeprint`/`afterprint` + `@media print`).
  - *Audience / Workflow Tabs (`.role-tabs[data-role-tabs]`)*: Contains one `[role="tablist"]` holding `[data-role-tab="<key>"]` buttons and matching `[data-role-panel="<key>"]` panels (never hardcode `hidden` on `[data-role-panel]` in static HTML — enforced by `scripts/check_manual_selectors.py`). `initRoleTabs()` in `<script data-manual-controls>` wires click selection plus `ArrowLeft`, `ArrowRight`, `Home`, and `End` keyboard navigation, while degrading to all panels visible cleanly when JS is disabled or during `@media print`.
- **Adaptive Dark/Light `--svg-*` Diagram Tokens**: Every Publication Manual declares the 19 semantic `--svg-*` tokens (`--svg-paper`, `--svg-surface`, `--svg-panel`, `--svg-ink`, `--svg-muted`, `--svg-soft`, `--svg-rule`, `--svg-accent`, `--svg-accent-tint`, `--svg-green`, `--svg-green-tint`, `--svg-blue`, `--svg-blue-tint`, `--svg-purple`, `--svg-purple-tint`, `--svg-amber`, `--svg-amber-tint`, `--svg-red`, `--svg-red-tint`) in `:root`, `@media (prefers-color-scheme: dark) { :root:not([data-theme="light"]) }`, and `html[data-theme="dark"]`. `.diagram-viewport` uses `background: var(--svg-paper)` (never hardcoded `#f5f5f5`/`#ffffff`), and inline `<svg>` elements use `var(--svg-*, <fallback>)` for fills, strokes, text, and markers so dark theme flips diagrams seamlessly.
- **Fullscreen Modal (`<dialog data-diagram-modal>`)**: Include exactly one document-level `<dialog data-diagram-modal>` (holding one `[data-diagram-modal-body]` and a `[data-diagram-close]`) per page. Each figure root carries `[data-diagram-open]` in its `.diagram-header`; the controller reparents the live root into the dialog and back so SVG IDs stay unique.
- **Ordered-Narrative Walkthroughs**: Ordered-narrative figures use `data-motion-mode="step"` (`3..7` steps, or `4` fixed phases `1: Removals`, `2: Moves`, `3: Modifications`, `4: Additions` when `data-semantic-pattern="architecture-delta"`, at most 2 items per step, loading complete at `step = count` / `data-frame="end"`) with one `[data-motion-controls]` bar and one `.diagram-annotation-banner[data-motion-status]` inside the root but outside the controls. Matrices, legends, and inventories use `data-motion-mode="none" data-step-count="0"` with the opener only.
- **Interactive Prompt Builder (`[data-prompt-builder]`)**: Mandatory standard whenever a document includes user-facing copyable prompts — author each as a `.prompt-card[data-prompt-builder]` card (with labeled inputs for every parameter/placeholder) rather than a raw `<pre><code>` block. **Omit completely when not needed**: if the document's topic/content does not require user prompts, omit the Sample Prompt Playbook section altogether (never add filler prompt cards). `initPromptBuilders()` in `<script data-manual-controls>` wires all cards automatically and is a no-op on pages without them:
  - *Structure*: `.prompt-card[data-prompt-builder]` holds `.prompt-card-head` (`.prompt-card-meta` + `.prompt-card-actions` with `.prompt-btn.primary[data-prompt-copy]` and optional `.prompt-btn[data-prompt-reset]`), an optional `.prompt-vars` responsive 2-column grid of `.prompt-field` (or `.prompt-field.full`) labeled `<input class="prompt-input" data-prompt-var="VAR_NAME" data-prompt-default="..." value="..." placeholder="...">`, a `.prompt-preview[data-prompt-output][data-prompt-template="..."]`, and a live-region `.prompt-status[data-prompt-status]` (`role="status" aria-live="polite" aria-atomic="true"`).
  - *Placeholders & Fallback*: Embed `{{VAR_NAME}}` (`[A-Za-z0-9_]+`) tokens in `data-prompt-template` with strict 1:1 parity against `[data-prompt-var]` inputs (zero orphan placeholders or unused inputs). Include complete static fallback text (default values or `<VAR_NAME>`) inside `[data-prompt-output]` so no-JS viewing stays complete; `[data-prompt-copy]` and `[data-prompt-reset]` remain hidden until `html[data-manual="ready"]` and in `@media print`.
  - *Preview & Copy*: `.prompt-preview` wraps multi-line text (`white-space: pre-wrap; overflow-wrap: anywhere; overflow-x: hidden`) with zero horizontal scrollbar. Live DOM rendering (`createTextNode` / `<span>`, never `innerHTML`) highlights unfilled placeholders as `<VAR_NAME>` (`.prompt-ph-empty`) and filled values (`.prompt-ph-filled`); `[data-prompt-copy]` copies exact plain text via shared `copyToClipboard()` (`navigator.clipboard.writeText()` with a hidden readonly `<textarea>` + `document.execCommand('copy')` fallback for `file:///` URLs).
- **Adaptive Code Blocks (`[data-code-block]`, 9-Line Auto-Collapse & CRLF Fix) & Blockquotes**: All command and code snippets use an adaptive editorial surface in both Light and Dark themes — never a pitch-black slab on light paper:
  - *Adaptive Tokens*: Declare `--code-bg`, `--code-header`, `--code-fg`, `--code-comment`, and `--code-border` in `:root` (Light: `#f4f6fa`, `#eaeef5`, `#1f2430`, `#5c6479`, `rgba(31, 36, 48, 0.14)`) and identically in both `@media (prefers-color-scheme: dark) { :root:not([data-theme="light"]) }` and `html[data-theme="dark"]` (Dark: `#161b26`, `#1d2433`, `#eef1f8`, `#8b95a8`, `rgba(255, 255, 255, 0.12)`).
  - *Declarative Markup*: Wrap snippets in `.code-block[data-code-block][data-wrap="on"]` (framed with `border-left: 3px solid var(--accent-blue)`, zero `box-shadow`) containing `.code-block-head` (`.code-block-meta` holding `.code-block-lang` + optional `.code-block-title`, and `.code-block-actions` holding `button.prompt-btn[data-code-wrap][aria-pressed="true"]` + `button.prompt-btn[data-code-copy]`), `<pre><code>...</code></pre>`, and a live-region `.code-status[data-code-status]` (`role="status" aria-live="polite" aria-atomic="true"`).
  - *CRLF Normalization, 9-Line Collapse, Wrap & Copy*: Soft-wrap is ON by default (`white-space: pre-wrap; overflow-wrap: anywhere; word-break: break-word; overflow-x: hidden`) with opt-in `Wrap: Off` (`data-wrap="off"`). `initCodeBlocks()` normalizes line endings via `rawCode.replace(/\r\n?/g, '\n').split('\n')`, styles `#` comment lines safely via DOM nodes (`.code-line-comment`, zero `innerHTML`), auto-collapses blocks with `> 9` lines (`data-code-collapsible="true" data-code-expanded="false"`, smooth `.code-block-fade` + `.code-block-foot` `[data-code-expand]` `Expand (N lines)` / `Collapse` button; opt out with `data-code-expanded="true"`), and always copies the full normalized code on `[data-code-copy]`. `[data-code-copy]`, `[data-code-wrap]`, and `[data-code-expand]` remain hidden until `html[data-manual="ready"]` and are hidden alongside `.code-block-actions` / `.code-block-foot` / `.code-block-fade` in `@media print` (where `<pre>` prints unclipped).
  - *Blockquotes*: Style `blockquote` with adaptive Light/Dark surfaces (`background: var(--paper-sidebar)`, `border: 1px solid var(--rule)`, `border-left: 3px solid var(--doc-accent)`, `color: var(--ink)`) and `break-inside: avoid` in `@media print`.
- **Emphasis & Fallbacks**: `.is-current` emphasis uses an accent stroke plus contrast, never a shadow or glow. Include one `<noscript>`, one `@media print`, and one `prefers-reduced-motion: reduce` block per document.

## 4. Multi-Document Portal & Verification Workflow

- **Multi-Diagram Deliverable**: Embed each `<svg>` inline directly into the document; never use `<object>`, `<img>`, or `<iframe>` tags. Provide external links to standalone `.svg` copies saved under `docs/diagrams/<slug>.svg`.
- **Multi-Document Architecture Portals**: Separate distinct domains or pillars into dedicated standalone HTML guides anchored by a master Portal index (`index.html`) whose sticky `toc-sidebar` groups documents and standalone SVG assets by domain. Assign stable row anchors (`id="<prefix>-<slug>"`) so counterpart tables cross-link directly (`<sibling>-guide.html#<id>`), and fulfill each manual's mandatory progressive diagram lens series using the **51 visual types** per [`references/diagram-series-matrix.md`](diagram-series-matrix.md).
- **Companion Archify Launcher Card (`.archify-companion-card`)**: Whenever a `diagram-design` manual has standalone companion `.archify/` workbench(es) or explainer(s), surface them inside the manual using the zero-shadow card grid from `assets/template-manual.html` (which includes `break-inside: avoid` in `@media print`):
  - Structure: `.archify-companion-grid` > `.archify-companion-card` containing `.archify-companion-head` (holding `.archify-companion-badge`), `<h3>`, `<p>`, and `<a class="archify-companion-btn" href="../.archify/..." target="_blank" rel="noopener">`.
  - Paths & Boundary: Link via relative `../.archify/...` or `../<project>/.archify/...` with `target="_blank" rel="noopener"`. NEVER embed Archify outputs via `<iframe>` or `<object>`, and NEVER inline or copy Archify HTML into `docs/`.
- **Portal Registration (`docs/catalog.json` → `docs/index.html`)**: Every manual created in `docs/*.html` MUST be registered in `docs/catalog.json`, declaring any companion views under the optional `"archify": [{"label": "...", "path": "../.archify/...", "kind": "workbench"|"explainer"}]` array (paths relative to `docs/`). Rebuild and validate the portal via:
  ```bash
  python3 docs/scripts/docs_engine.py build
  python3 docs/scripts/docs_engine.py verify
  ```
  `build` regenerates `docs/index.html` using valid HTML5 with zero nested `<a>` tags (outer `<div class="doc-card">` with sibling `<a class="doc-card-primary">` and `<div class="doc-archify-bar">` `.doc-archify-pill` links) and auto-runs `verify`, enforcing `0` unindexed `docs/*.html` files, `0` broken Archify links (and valid `"workbench"|"explainer"` kinds), valid standalone XML 1.0 SVGs, and `self_check.py`-clean HTML.
- **Size inline badges and connector masks to `height="16"` in multi-diagram manuals**: `scripts/self_check.py --verify-geometry` scans `<rect>` elements across the entire HTML file rather than scoping per `<svg>`, classifying any `20..200px × 8..14px` rect as a connector label mask and failing if any `≥60×40px` node in a *later* `<svg>` shares those `(x, y)` coordinates; `16px`-tall badges and masks align to the 4px grid and avoid false cross-figure clipping errors.
- **SSOT CSS/JS Synchronization & Stage 4 Verification (`visual_audit.py`)**: Edit shared CSS/JS only in `assets/manual-shared.css` and `assets/manual-shared.js`, project into `assets/template-manual.html` and KB `src/kb/shell/shell.{css,js}`, propagate `<script data-manual-controls>` to manuals, and run the single-command Stage 4 auditor:
  ```bash
  python3 scripts/sync_manual_controls.py --sync-shell --write
  python3 scripts/sync_manual_controls.py --write <pages>
  python3 scripts/visual_audit.py --require-archetype <pages>
  python3 docs/scripts/docs_engine.py verify --visual
  ```
  `scripts/visual_audit.py` deterministically runs all 5 checks in one pass (`self_check.py --verify-geometry` + `check_manual_selectors.py`, v2.7 IA density + 5-archetype mandatory lens/waiver ratchet via `scripts/diagram_registry.py` + pure LF + local/companion links, SSOT CSS/JS parity, headless Chromium `1440×900` Light/Dark + `375×812` mobile zero-overflow & interactive controls, and KB `CanonicalManualExtractor` round-trip).
